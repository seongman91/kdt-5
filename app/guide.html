설치하는 프로그램과 사용하는 계정

WSL 2와 Docker Desktop을 설치합니다. API와 터널 프로그램은 Docker 안에서 실행하므로 Python·Git·IBM Cloud CLI를 Windows에 따로 설치하지 않습니다. Orchestrate는 기존 교육용 SaaS 계정으로 로그인합니다.

처음부터 따라 할 순서

  • 2~4쪽: PC 점검 → WSL 설치 → 재부팅 → Docker 설치와 확인
  • 5~7쪽: 압축 해제 → 01_Start.cmd 실행 → 02_Check.cmd 점검
  • 8~11쪽: HR·은행 도구 가져오기 → Agent 연결 → 실제 호출 확인
  • 12쪽: 03_Stop.cmd로 종료 → 다음 실행 시 바뀐 주소 갱신
  • 13~16쪽: 오류 해결, 도움 요청, 최종 완료 체크

설치와 재부팅을 포함해 40~90분 정도를 확보합니다. Docker가 이미 준비되어 있다면 5쪽부터 진행합니다. 이 서버에는 가상의 교육 데이터만 사용합니다. 공개 주소를 아는 사람이 데이터를 조회·변경할 수 있으므로 실습 후 중지하세요.

완료 확인 최종 목표: 본인 SaaS Agent가 본인 PC의 데이터를 도구로 조회하고, 승인한 변경 후 다시 조회한 결과가 일치합니다.

설치 전에 PC와 계정을 확인하기

1 Windows와 하드웨어

Windows 시작 메뉴에서 winver를 검색해 실행합니다. 이 가이드는 현재 지원되는 Windows 11 64비트와 Intel/AMD PC를 기본 경로로 설명합니다. Windows 10은 Microsoft 지원 상태와 현재 Docker 지원 조건을 먼저 확인하세요. Windows Server는 이 설치 경로의 대상이 아닙니다.

항목확인 방법과 기준
메모리작업 관리자 → 성능 → 메모리. Docker 문서 기준 최소 8 GB, 본 실습은 16 GB를 권장합니다.
가상화Ctrl + Shift + Esc → 성능 → CPU → 가상화가 사용 또는 Enabled인지 확인합니다.
디스크설치·이미지 다운로드용 여유 공간을 확보합니다. 본 실습 권장 여유는 20 GB입니다.
프로세서설정 → 시스템 → 정보 → 시스템 종류. Intel/AMD는 x86_64 또는 AMD64 설치 파일을 사용합니다. ARM PC는 별도 ARM 지원 여부를 확인합니다.

2 권한과 교육 계정

  • WSL 기능을 처음 켤 때는 관리자 권한이 필요할 수 있습니다. 회사 PC라면 IT 관리자에게 설치 권한을 요청합니다.
  • Orchestrate SaaS 로그인과 Agent·Tool 생성 권한을 확인합니다. 이 ZIP은 Orchestrate 계정을 만들지 않습니다.
  • 교육에서 배정된 학생 번호 S01~S20을 준비합니다. 같은 SaaS 인스턴스를 쓰는 사람끼리 번호가 중복되지 않아야 합니다.

Docker Desktop은 교육용 사용 등에 무료 조건이 있지만 모든 조직에서 항상 무료인 것은 아닙니다. 회사 PC에서는 조직의 Docker 이용 정책과 라이선스 조건을 확인합니다.

완료 확인 Windows 지원 조건, 가상화 Enabled, 설치 권한, SaaS 로그인, 학생 번호가 준비되어야 다음으로 진행합니다.

STEP 03 / 16

WSL 2를 설치하고 Windows 재부팅하기

WSL 2는 Windows에서 Linux 기반 프로그램을 실행하는 기능입니다. 이 실습은 Docker가 WSL 2를 이용해 Linux 컨테이너를 실행하도록 설정합니다.

1 관리자 PowerShell 열기

시작 메뉴에서 PowerShell을 검색합니다. Windows PowerShell을 마우스 오른쪽 버튼으로 눌러 관리자 권한으로 실행을 선택합니다. 권한 확인 창이 나오면 본인 PC 또는 승인받은 PC에서 허용합니다.

2 WSL 설치

wsl --install

설치가 완료되면 열어 둔 작업을 저장하고 Windows를 재부팅합니다. 이미 설치되어 있다는 안내가 나오면 기존 배포판을 삭제하지 말고 아래 업데이트 단계로 넘어갑니다.

3 재부팅 후 업데이트와 버전 확인

wsl --update
wsl --version
wsl --set-default-version 2

WSL 버전이 표시되어야 합니다. Docker 공식 문서는 WSL 2.1.5 이상을 요구하므로 가능하면 최신 WSL로 업데이트합니다. wsl --version에 버전 대신 도움말만 나오면 오래된 WSL일 수 있습니다. 설치 안내와 업데이트 오류를 확인하세요.

Ubuntu 창이 열렸을 때

기본 설치 과정에서 Ubuntu가 함께 설치될 수 있습니다. 새 사용자 이름과 암호를 요구하면 Linux용 계정을 만듭니다. 암호 입력 중 화면에 글자가 표시되지 않는 것은 정상입니다. 이 안내서의 다음 명령은 Ubuntu 창이 아니라 Windows PowerShell에서 실행합니다.

완료 확인 재부팅을 마쳤고 wsl --version에서 버전을 볼 수 있으면 완료입니다. 가상화 오류가 계속되면 13쪽의 설치 오류 해결을 확인합니다.

STEP 04 / 16

Docker Desktop 설치와 실행 확인하기

1 공식 설치 파일 받기

Docker Desktop Windows 설치 안내 열기

공식 페이지에서 본인 CPU에 맞는 Windows 설치 파일을 받습니다. 일반적인 Intel/AMD 노트북은 x86_64 또는 AMD64입니다. 설치 마법사에 WSL 2 사용 항목이 있으면 선택합니다. 설치 또는 Windows가 재부팅을 요청하면 재부팅합니다.

2 Docker Desktop 시작

시작 메뉴에서 Docker Desktop을 실행하고 약관을 확인합니다. 로그인 건너뛰기가 제공되고 조직 정책이 허용하면 Docker 계정 로그인 없이 이 실습을 진행할 수 있습니다. 조직이 로그인을 요구하면 제공받은 계정을 사용합니다.

3 Linux 컨테이너와 WSL 설정

Settings → General에서 Use the WSL 2 based engine 항목이 있으면 켭니다. 메뉴에 Switch to Linux containers가 보이면 눌러 Linux 모드로 전환합니다. Switch to Windows containers라고 보이면 현재 Linux 모드일 수 있으므로 전환하지 않습니다. Engine running 상태가 될 때까지 기다립니다.

4 일반 PowerShell에서 확인

docker version
docker compose version
docker info --format '{{.OSType}}'
docker run --rm hello-world

docker version에 Client와 Server가 모두 나타나고, OSType 결과가 linux여야 합니다. 마지막 명령에서 Hello from Docker!를 확인합니다. hello-world는 설치 확인용이며 실습 API가 아닙니다.

완료 확인 Server 정보, linux, Hello from Docker!를 확인하면 설치 완료입니다. 이후 Windows PowerShell은 일반 권한으로 사용합니다.

위 메시지가 두 주소에서 각각 나오면 점검 성공입니다. Only localhost was checked 경고가 나오면 외부 연결은 아직 완료되지 않았습니다. 공개 주소의 검사도 통과한 뒤 다음으로 진행합니다.

응답 코드 200과 직원 이름·주소·휴가 잔여일이 표시되면 성공입니다. /health는 서버 상태만 확인하므로 직원 조회도 직접 확인합니다.

완료 확인 로컬·공개 주소의 점검을 모두 통과했으면 8쪽에서 Orchestrate에 HR 도구를 가져옵니다.

순서대로 직접 확인하기

  • WSL과 Docker Linux 엔진을 확인했다.
  • 01_Start.cmd를 실행해 본인의 공개 주소를 받았다.
  • 02_Check.cmd에서 로컬·공개 주소의 직원·계좌 조회를 모두 통과했다.
  • 생성된 HR·은행 YAML을 인증 없이 가져오고 본인 Agent에 연결했다.
  • HR 변경 후 재조회 결과와 실제 Tool Trace가 일치했다.
  • 은행 조회와 배포 후 읽기 요청을 확인했다.
  • 03_Stop.cmd와 다음 실행 시 주소 갱신 방법을 안다.

검증 범위

배포 파일은 Windows PowerShell 5.1과 Docker에서 인증 없는 시작·조회·변경·중지·재실행을 검증했습니다. 저장된 데이터 보존과 기존 API의 동시 저장 테스트도 확인했습니다. 새 PC의 WSL 설치 전체 과정, 각 교육생의 네트워크와 실제 Orchestrate 테넌트의 도구 가져오기·Live 호출은 단계별 완료 기준에 따라 확인해야 합니다.
